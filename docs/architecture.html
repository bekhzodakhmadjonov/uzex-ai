UZEX Agent Architecture

How our selection-stage agent answers questions about 500,000 exchange deals in Uzbek and Russian without being able to invent a figure.

1. The idea in one picture

Most teams will let a model read data and write an answer. Ours splits the work. Models only propose text: a SQL query and a sentence with blanks. Code runs the query and fills the blanks, so every number and company name in an answer comes from the database.

2. How each failure is blocked

What could go wrongWhat stops itHow we know
Model types a wrong number or fake company into the answerIt writes {{0.n_deals}} style blanks. Any digit or legal-form name it types is rejected, unless the digit came from the question.Unit tests. The check rejected real drafts in the last run.
Model writes valid SQL that answers the wrong questionA second model writes its own query. If results differ, the main model reads both and picks.Picked the right query in 10 of 10 tests with a planted wrong query.
Refusal text contains an invented factFigures, company forms and table names in a refusal trigger a fixed, pre-written refusal.Unit tests. Models are also told to describe only what the registry holds.
Empty result gets dressed up as an answerZero rows or all-zero totals skip the model and return a fixed "no matching deals" message.14 of 14 on held-out refusal and zero-result questions.
Messy names undercount a product927 raw spellings map to 44 products and 41 families. Queries filter on keys.Counts match the raw CSVs, computed separately with pandas.
Units or currencies get mixedPrices are grouped by unit and currency. Copper shows dollars and sums separately.Benchmark cases built to catch exactly this pass.
Malicious or runaway SQLDuckDB's own parser allows one SELECT. System tables and file readers are blocked. Read-only connection, 8 second limit, 3 GB memory limit.Attack queries in the test suite. A cross-join was interrupted at 8 seconds.

3. Which AI model, and what it costs

Recommendation: three cheap Gemini Flash models, each doing the job it is good enough for. One question costs about 1.5 US cents, so the 10 judged questions cost about 15 cents. Budget is not the limit here, and accuracy is worth far more than the one cent we could save.

What about Claude?

Not as the default. Opus and Sonnet are expensive for this job, but Claude is not expensive across the board. Haiku 5.5 lists at $0.10 per million input tokens, which is cheaper than all the Gemini models above.

4. Data layer

A build script turns the raw CSVs and our hand-checked catalog into one DuckDB file in about 10 seconds. The build stops if any product name is unmapped or a known total does not match. Models see one wide table so they rarely need joins.

TableRowsWhat it holds
deals500,000One row per deal with everything joined: product family and grade, volume, unit price, amounts in sums and dollars at the deal-date rate, status flags, payment and delivery deadlines, delay days, party and broker names.

participants14,392Companies: 392 sellers and 14,000 buyers, region, activity, VAT status.
brokers120Broker offices, BK001 to BK120.
usd_rates1,765Dollar rate for every calendar day.

Exchange rule we chose: deal counts cover the whole registry with annulled deals shown alongside. Money, volume and price lead with the figure excluding annulled deals, because the dataset README says such a deal did not take place, and the all-deals figure is shown next to it.

6. Deployment plan

A judge's phone reaches Caddy over HTTPS on a free DuckDNS name. Caddy forwards to one FastAPI process, which serves the page and the API, opens the database file read-only, and calls the Gemini API. It all runs in Docker Compose on the Oracle free ARM server. An Azure VM using the same files is the standby: if Oracle fails, we point DuckDNS at Azure.

Status: nothing is deployed. The Docker daemon was off on the dev machine, so the image has not been built. A clean install from the pinned requirements did start and answer. ARM and HTTPS are untested until the first real deploy, so do it early.
